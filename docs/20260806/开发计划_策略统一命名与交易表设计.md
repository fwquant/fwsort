## 一、需求概述

### 1.1 背景

当前系统中"我的执行账户"和"自动任务"两个功能几乎完全一样，且概念分散：信号源(SignalProvider)、自动任务(AutoTask)、执行账户(ExecutionAccount) 三个概念在 UI 和字段中混用，对外不统一。外部（如 Win7 版本）称为"策略"，而当前系统创造了"执行账户"这个新词，导致用户理解困难。

### 1.2 核心目标

1. **统一命名为"策略"**：将"信号源""自动任务""执行账户"统一为"策略"和"自动策略"两个概念
2. **表名重命名**：`auto_task` → `auto_strategy`、`auto_task_log` → `auto_strategy_log`、`execution_account` → `auto_strategy_account`
3. **模块合并**：`fwsort/signals/` + `fwsort/tasks/` 合并为 `fwsort/strategy/`，功能不减
4. **新增策略交易明细表**：支撑胜率、盈亏比、回撤率、夏普比率等统计指标
5. **复用现有 UI 交互**：保留"我的执行账户"首页排行榜和图表的直观展示方式

### 1.3 概念统一映射

```
策略(Strategy) ──1:N──→ 自动策略(AutoStrategy)
  ↑ 原信号源              ↑ 原自动任务+执行账户(合并)
  SignalProvider          AutoTask + ExecutionAccount
  (.py文件定义)           (用户创建的执行实例)
```

| 旧概念 | 新概念 | 说明 |
|---|---|---|
| 信号源(SignalProvider) | **策略(Strategy)** | .py 文件定义，包含信号产生+下单逻辑+风控参数 |
| 自动任务(AutoTask) | **自动策略(AutoStrategy)** | 用户选择一个策略+配置资金/间隔，创建执行实例 |
| 执行账户(ExecutionAccount) | **自动策略账户(AutoStrategyAccount)** | 资金账户（与自动策略 1:1，保留为独立表） |
| 我的执行账户 | **我的自动策略** | 首页排行榜页面 |
| 信号管理 | **策略管理** | admin 控制台 Tab |
| 自动任务 | **自动策略** | admin 控制台 Tab |
| 任务日志 | **策略日志** | admin 控制台 Tab |
| 任务状态 | **策略状态** | 状态页面 |
| 执行任务 | **执行策略** | 执行流水线页面 |

### 1.4 关系说明

- **一个策略 → N 个自动策略**：如"BTC 4h 涨跌策略"可被多个用户各自创建自动策略实例
- **自动策略**包含：关联的策略(策略名) + 资金账户(余额/风控) + 调度参数(间隔/循环) + 绩效统计
- **具体的"信号方向"**（UP/DOWN）：用"方向"或"投票方向"替代"信号方向"这个词
- **保留 providers 目录**：用户自定义策略 Providers 目录 `fwsort/strategy/providers/` 保持不变

### 2.2 表迁移策略

采用 **ALTER TABLE RENAME** + **保留旧视图别名** 的方式：

```sql
-- 1. 重命名表
ALTER TABLE auto_task RENAME TO auto_strategy;
ALTER TABLE auto_task_log RENAME TO auto_strategy_log;
ALTER TABLE execution_account RENAME TO auto_strategy_account;

-- 2. 更新外键引用（auto_strategy_log.task_id → auto_strategy_log.strategy_id）
-- 注：SQLite 不支持直接改列名，需要重建表；PostgreSQL/MySQL 支持

-- 3. 创建旧表名视图（兼容期，便于回滚）
CREATE VIEW IF NOT EXISTS auto_task AS SELECT * FROM auto_strategy;
CREATE VIEW IF NOT EXISTS auto_task_log AS SELECT * FROM auto_strategy_log;
CREATE VIEW IF NOT EXISTS execution_account AS SELECT * FROM auto_strategy_account;
```

## 六、新增表结构

### 6.1 `strategy_trade`（策略交易明细表）

```text
class StrategyTrade(Base):
    """策略交易明细表 - 每笔已成交的交易记录（含持仓中与已平仓）"""
    __tablename__ = "strategy_trade"

    # === 主键与策略关联 ===
    id = Column(PKType, primary_key=True, autoincrement=True)
    trade_uid = Column(String(64), unique=True, index=True, nullable=False)
    # 交易唯一ID，格式: TRD-{yyyymmdd}-{8hex}

    # 策略维度（统计排行榜的核心）
    strategy_name = Column(String(128), nullable=False, index=True)  # 策略名
    auto_strategy_id = Column(FKType, ForeignKey("auto_strategy.id"), nullable=True, index=True)  # 关联自动策略
    account_id = Column(FKType, ForeignKey("auto_strategy_account.id"), nullable=True, index=True)  # 关联账户

    # 策略来源（.py 文件定义的策略名）
    source_strategy = Column(String(64), default="", index=True)  # 引用的策略名

    # 标的维度
    platform = Column(String(32), nullable=False)  # polymarket/okx
    symbol = Column(String(64), default="")  # 交易对/市场标识
    market_question = Column(String(512), default="")  # Polymarket 市场问题
    market_slug = Column(String(128), default="")  # 市场 slug

    # === 交易核心字段 ===
    direction = Column(String(16), default="", index=True)  # 方向: UP/DOWN/NEUTRAL
    side = Column(SmallInteger, nullable=False)  # 1-买入 2-卖出
    order_type = Column(SmallInteger, default=2)  # 1-限价 2-市价
    order_id = Column(String(128), default="", index=True)  # 交易所订单ID

    # 价格与数量
    entry_price = Column(Float, nullable=False)  # 开仓价（成本价）
    exit_price = Column(Float, nullable=True)  # 平仓价（结算价）
    quantity = Column(Float, default=0.0)  # 数量
    amount_usd = Column(Float, nullable=False)  # 下单金额 USDC

    # === 盈亏字段（核心统计字段，可 SQL 直接聚合）===
    pnl_amount = Column(Float, default=0.0)  # 盈亏金额 USD
    pnl_percent = Column(Float, default=0.0)  # 盈亏百分比 %
    is_profit = Column(Boolean, default=False, index=True)  # 是否盈利
    is_win = Column(Boolean, default=False, index=True)  # 是否胜利（方向判断正确）

    # === 时间字段 ===
    entry_at = Column(DateTime, nullable=False, index=True)  # 开仓时间
    exit_at = Column(DateTime, nullable=True, index=True)  # 平仓时间
    hold_duration_seconds = Column(Integer, default=0)  # 持仓时长（秒）

    # === 状态字段 ===
    status = Column(SmallInteger, default=0, index=True)
    # 0-持仓中 1-已平仓盈利 2-已平仓亏损 3-已平仓持平 4-已撤销 5-失败

    market_resolved = Column(Boolean, default=False, index=True)  # 市场是否已结算
    resolved_at = Column(DateTime, nullable=True)  # 结算时间

    # === 风控与执行质量 ===
    slippage = Column(Float, default=0.0)  # 滑点
    latency_ms = Column(Integer, default=0)  # 下单延迟
    execution_detail_json = Column(Text, default="{}")  # 执行详情
    result_detail_json = Column(Text, default="{}")  # 结果详情

    # === 软删除与时间戳 ===
    deleted_at = Column(DateTime, nullable=True, index=True)
    created_at = Column(DateTime, server_default=func.now(), index=True)
    updated_at = Column(DateTime, server_default=func.now(), onupdate=func.now())

    __table_args__ = (
        Index("idx_strategy_trade_name_time", "strategy_name", "entry_at"),
        Index("idx_strategy_trade_name_status", "strategy_name", "status"),
        Index("idx_strategy_trade_profit", "strategy_name", "is_profit"),
        Index("idx_strategy_trade_source", "source_strategy", "entry_at"),
    )
```

### 6.2 `strategy_equity_curve`（净值曲线表）

```text
class StrategyEquityCurve(Base):
    """策略净值曲线 - 每日快照，支撑资金曲线图和回撤曲线图"""
    __tablename__ = "strategy_equity_curve"

    id = Column(PKType, primary_key=True, autoincrement=True)

    # 策略维度
    strategy_name = Column(String(128), nullable=False, index=True)
    auto_strategy_id = Column(FKType, ForeignKey("auto_strategy.id"), nullable=True, index=True)
    account_id = Column(FKType, ForeignKey("auto_strategy_account.id"), nullable=True, index=True)

    # === 净值数据 ===
    snapshot_date = Column(DateTime, nullable=False, index=True)  # 快照时间（每日）
    equity = Column(Float, nullable=False)  # 净值 USDC
    balance = Column(Float, nullable=False)  # 余额 USDC
    daily_pnl = Column(Float, default=0.0)  # 当日盈亏 USDC
    daily_pnl_percent = Column(Float, default=0.0)  # 当日盈亏 %

    # === 回撤数据 ===
    peak_equity = Column(Float, default=0.0)  # 历史峰值净值
    drawdown = Column(Float, default=0.0)  # 当前回撤 USDC
    drawdown_percent = Column(Float, default=0.0)  # 当前回撤率 %
    max_drawdown_percent = Column(Float, default=0.0)  # 历史最大回撤率 %

    # === 持仓数据 ===
    position_count = Column(Integer, default=0)  # 当日持仓数
    trade_count = Column(Integer, default=0)  # 当日交易数

    created_at = Column(DateTime, server_default=func.now())

    __table_args__ = (
        Index("idx_equity_strategy_date", "strategy_name", "snapshot_date"),
        Index("idx_equity_account_date", "account_id", "snapshot_date"),
    )
```

class AutoStrategy(Base):
    # ... 现有字段保持不变 ...

    # === 新增：资金与统计字段 ===

    total_trades = Column(Integer, default=0)  # 总交易次数

    loss_trades = Column(Integer, default=0)  # 亏损次数

    max_drawdown = Column(Float, default=0.0)  # 最大回撤率 %

    # === 新增：策略关联字段 ===

## 八、风险与注意事项

### 8.1 数据库迁移风险（高）

- **SQLite 限制**：SQLite 不支持直接改列名，需要重建表。建议：
  1. 备份 `data/fwsort.db`
  2. 创建新表 → 复制数据 → 删除旧表 → 重命名新表
  3. 创建旧表名视图（兼容期）
- **外键约束**：`auto_strategy_log.strategy_id` 引用 `auto_strategy.id`，需同步更新
- **回滚方案**：保留旧表视图，可随时回退

### 8.2 Celery 任务名迁移（高）

- **风险**：Celery 任务名是字符串字面量，改名会导致正在排队的任务找不到对应函数
- **方案**：
  1. 先停止所有 Celery worker
  2. 迁移代码（更新任务名）
  3. 清空 Redis 队列
  4. 重启 worker
- **涉及**：`fwsort.scheduler.auto_task_dispatcher`→`fwsort.scheduler.auto_strategy_dispatcher`、`fwsort.scheduler.execute_auto_task`→`fwsort.scheduler.execute_auto_strategy`

### 8.3 Redis 键迁移（中）

- **风险**：`fwsort:auto_task:last_run` 存储调度器上次运行时间，改名会丢失状态
- **方案**：启动时检测旧键存在则迁移到新键
- **涉及**：`fwsort/strategy/dispatcher.py:21`、`fwsort/strategy/service.py:25`、`fwsort/scheduler.py:625`

### 8.4 模块合并的 import 风险（中）

- **风险**：`fwsort.signals.providers` 包被动态 import（`import fwsort.signals.providers as providers_pkg`），改名后需同步更新
- **涉及**：`fwsort/strategy/manager.py`（3 处动态 import）、`test_reload.py`
- **方案**：全项目搜索 `fwsort.signals` 和 `fwsort.tasks`，逐一替换

### 8.5 API 兼容性（低）

- **方案**：旧路由保留 3 个版本，通过别名转发到新路由
- **前端**：JS 中 API 路径统一改为新路由（27 处 `/api/tasks` + 13 处 `/api/signal-providers`）

### 8.6 数据回填

- `strategy_trade` 表初始为空，需要从 `auto_strategy_log` 历史数据回填（仅成功且成交的记录）
- `strategy_equity_curve` 表初始为空，资金曲线从有交易数据开始累积
- `auto_strategy` 表新增统计字段初始为 0，需要从 `strategy_trade` 聚合回填

### 8.7 性能考虑

- `strategy_trade` 表预计数据量：每策略每日 10-50 条，100 个策略每年约 36-180 万条
- 索引设计已覆盖主要查询场景（按策略+时间、按策略+状态）
- 资金曲线按日聚合，数据量小（每策略每年 365 条）
