## 一、需求背景

### 1.1 问题

风控参数和逻辑原先散落在多个模块中：

| 位置 | 风控逻辑 | 问题 |
|---|---|---|
| `strategy/service.py` `_run_risk_control()` | 每日次数上限、每日金额上限 | 与业务逻辑耦合，难以复用 |
| `strategy/service.py` `_check_circuit_breaker()` | 连续失败熔断 | 冻结逻辑直接改 `AutoStrategy` 字段 |
| `voting.py` 风控1 | 日亏损比例冻结 | 冻结逻辑直接改 `ExecutionAccount.risk_frozen` |
| `voting.py` 风控2 | 单笔金额比例截断 | 与 voting 业务混在一起 |
| `agent_router.py` | 投票前预检查 | 重复实现冻结逻辑 |
| `scheduler.py` | 账户冻结过滤 | 直接读 `risk_frozen` 字段 |

**核心痛点**：
1. **冻结状态 3 处各自修改**：`strategy/service.py`、`voting.py`、`agent_router.py` 各自直接改 `risk_frozen`，容易不一致
2. **参数散落在两张表的字段上**：`AutoStrategy`（max_daily_amount/max_daily_count/max_consecutive_failures）和 `ExecutionAccount`（risk_frozen/risk_frozen_reason），无法统一管理
3. **无审计日志**：风控触发后无法追溯"什么时候什么规则拦截了什么订单"
4. **无法做模板复用**：每个账户/策略独立配置，无法批量套用"保守型/激进型"模板
5. **规则硬编码**：增删规则需要改业务代码，无法灵活启停

### 1.2 目标

将风控功能独立为与策略模块平级的新模块 `fwsort/risk/`，实现：

1. **统一入口**：所有交易路径（自动策略下单、投票表决、手动下单）走同一个 `RiskControlService` Facade
2. **可插拔规则链**：每条规则独立一个类，按场景组合（pre_vote / pre_order / post_settle）
3. **三级参数合并**：实例个性化覆盖 → 关联模板 → 全局默认
4. **冻结状态唯一真源**：`AccountRiskProfile.is_frozen` 为唯一真源，`ExecutionAccount.risk_frozen` 为镜像
5. **完整审计**：每次风控检查（通过/拦截/冻结）都写入 `RiskEventLog`
6. **前端可视化管理**：风控参数配置 + 事件日志查询页面

```

  关联模板字段（RiskProfile）

  全局默认值（settings.RISK_SINGLE_RATIO 等）
```

```text
# manager.py 核心逻辑
merged = global_defaults()          # 第3级：全局默认
if template:
    for f in param_fields:
        if getattr(template, f) is not None:
            merged[f] = getattr(template, f)   # 第2级：模板覆盖
if instance:
    for f in param_fields:
        if getattr(instance, f) is not None:
            merged[f] = getattr(instance, f)   # 第1级：实例覆盖
```

## 四、可插拔规则链设计

### 4.1 规则基类

```text
class BaseRiskRule:
    rule_name: str = "BaseRiskRule"

    def check(self, ctx: RiskContext) -> RuleResult:
        raise NotImplementedError
```

### 4.2 规则执行结果

```text
@dataclass
class RuleResult:
    rule_name: str
    passed: bool                     # True=放行 / False=拦截
    message: str = ""                # 用户可读说明
    amount_cap: float | None = None  # 非 None=允许此单但截断金额到此值
    should_freeze: bool = False      # True=要求触发账户冻结
    freeze_reason: str = ""          # 冻结说明
    detail: dict = field(...)        # 结构化详情（写审计日志用）
```

### 4.3 已实现的 5 条规则

| # | 规则类名 | 来源 | 作用 | 触发动作 |
|---|---|---|---|---|
| 1 | `DailyCountLimitRule` | 原 `strategy/service._run_risk_control` | 当日下单次数达上限 → 拦截 | 拦截（不冻结） |
| 2 | `DailyAmountLimitRule` | 原 `strategy/service._run_risk_control` | 当日下单总额达上限 → 拦截；加此单会超限 → 拦截 | 拦截（不冻结） |
| 3 | `ConsecutiveFailureRule` | 原 `strategy/service._check_circuit_breaker` | 连续失败次数达阈值 → 冻结 + 停止任务 | **冻结** |
| 4 | `SingleOrderRatioRule` | 原 `voting.py` 风控2 | 单笔金额 > 余额×比例 → 截断金额（不拦截） | 截断放行 |
| 5 | `DailyLossRatioRule` | 原 `voting.py` 风控1 | 日亏损比例 ≥ 阈值 → 冻结账户 | **冻结** |

### 4.4 规则集合（按场景分组）

```text
# 投票前检查（voting.py / agent_router.py 调用）
PRE_VOTE_RULES = [
    DailyLossRatioRule,       # 先看有没有日亏冻结
    SingleOrderRatioRule,     # 金额截断
]

# 自动策略下单前检查（strategy/service.py 调用）
PRE_ORDER_AUTO_STRATEGY_RULES = [
    DailyCountLimitRule,
    DailyAmountLimitRule,
    ConsecutiveFailureRule,
    SingleOrderRatioRule,
    DailyLossRatioRule,
]

# 结算后检查（订单结算完触发）
POST_SETTLE_RULES = [
    DailyLossRatioRule,       # 结算后扫日亏
]
```

### 4.5 扩展新规则

只需 3 步，无需修改业务代码：

```text
# 1. 在 rules.py 新增规则类
class MaxDrawdownRule(BaseRiskRule):
    rule_name = "MaxDrawdownRule"

    def check(self, ctx: RiskContext) -> RuleResult:
        ratio = ctx.effective_params.get("max_drawdown_ratio")
        if ratio and ctx.drawdown_percent >= ratio:
            return RuleResult(
                self.rule_name, False,
                should_freeze=True,
                freeze_reason=f"最大回撤 {ctx.drawdown_percent:.1%} >= {ratio:.0%}",
            )
        return RuleResult(self.rule_name, True)

# 2. 加入对应规则集合
PRE_ORDER_AUTO_STRATEGY_RULES.append(MaxDrawdownRule)

# 3. 完成（自动被 RiskControlService 调用）
```

## 五、统一入口 Facade

### 5.1 RiskControlService 方法清单

| 方法 | 调用方 | 作用 |
|---|---|---|
| `check_before_auto_strategy_order()` | `strategy/service.py` | 自动策略下单前：跑 5 条规则链 |
| `check_before_vote()` | `voting.py`、`agent_router.py`、`scheduler.py` | 投票前：跑 2 条规则链 |
| `post_settle_check()` | `strategy/service.py`（结算后） | 结算后：扫日亏冻结 |
| `freeze_account()` | 上述方法内部 + `risk_router.py` 手动冻结 | 冻结账户（唯一入口） |
| `unfreeze_account()` | `risk_router.py` 手动解冻 | 解冻 + 清零连续失败 |
| `is_account_frozen()` | `scheduler.py` | 读取冻结状态 |
| `update_strategy_consecutive_failures()` | `strategy/service.py` | 更新策略连续失败计数 |

### 5.2 冻结操作的唯一入口

```text
# 严禁其他模块直接改 ExecutionAccount.risk_frozen
# 必须通过 RiskControlService.freeze_account()：

RiskControlService.freeze_account(db, account_id, reason="日亏损超过30%")
# 内部完成：
#   1. AccountRiskProfile.is_frozen = True（真源）
#   2. ExecutionAccount.risk_frozen = True（镜像兼容）
#   3. 写 RiskEventLog 审计日志
#   4. 发 Notification 通知用户（1天内不重复）
```

### 5.3 RiskContext（风控上下文）

调用方把能提供的信息都填入 `RiskContext`，规则只读取自己需要的字段，缺失时直接放行：

```text
@dataclass
class RiskContext:
    stage: str = "pre_order"          # pre_vote / pre_order / post_settle / manual
    order_amount_usd: float | None    # 本笔订单金额
    account_id: int | None            # 账户ID
    account_balance: float            # 账户余额
    account_daily_pnl: float          # 当日盈亏
    account_initial_balance: float    # 初始余额
    account_is_frozen: bool           # 当前是否已冻结
    auto_strategy_id: int | None      # 策略ID
    strategy_max_daily_amount: float  # 策略级日金额上限
    strategy_max_daily_count: int     # 策略级日次数上限
    strategy_max_consecutive_failures: int  # 连续失败阈值
    strategy_consecutive_failures: int      # 当前连续失败次数
    today_total_amount: float         # 当日已下单总额
    today_total_count: int            # 当日已下单次数
    effective_params: dict            # 三级合并后的有效参数
    extra: dict                       # 额外上下文（审计用）
```

### 6.1 已接入的 6 个调用点

| # | 文件 | 原逻辑 | 新逻辑 |
|---|---|---|---|
| 1 | `strategy/service.py` | `_run_risk_control()` 内联检查 | `RiskControlService.check_before_auto_strategy_order()` |

| 5 | `agent_router.py` | 重复实现冻结逻辑 | `RiskControlService.check_before_vote()` + `freeze_account()` |
| 6 | `scheduler.py` | 直接读 `risk_frozen` 字段过滤 | `RiskControlService.is_account_frozen()` |

### 6.2 接入示例（strategy/service.py）

```text
# 修改前：
risk_check = _run_risk_control(db, task, task_id)
if not risk_check["passed"]:
    return risk_check

# 修改后：
from fwsort.risk.service import RiskControlService

risk_result = RiskControlService.check_before_auto_strategy_order(
    db, auto_strategy_id=task_id, manual=manual
)
if not risk_result.passed:
    return {"passed": False, "reason": risk_result.message}
if risk_result.amount_cap is not None:
    order_amount = min(order_amount, risk_result.amount_cap)
```

## 十二、设计决策记录

### Q1：为什么冻结状态用 `AccountRiskProfile.is_frozen` 而不是 `ExecutionAccount.risk_frozen`？

**决策**：`AccountRiskProfile.is_frozen` 为唯一真源，`ExecutionAccount.risk_frozen` 降级为镜像字段。

**原因**：
1. 风控模块应自管理状态，不依赖业务表的字段语义
2. `AccountRiskProfile` 还存储了 `frozen_reason`、`frozen_at`、`last_check_at` 等风控专属字段
3. 兼容期内保留镜像字段，其他模块（如 scheduler 的快速过滤）无需立即改造

### Q2：为什么 `SingleOrderRatioRule` 截断金额而不是拦截？

**决策**：单笔金额超比例时，截断到 `balance × ratio` 并放行。

**原因**：保持与原 `voting.py` 风控2 的行为一致。投票表决产生的下单金额可能偏大，截断比直接拦截更合理（不丢失交易机会）。

### Q3：为什么规则链中遇到 freeze=True 就停止后续规则？

**决策**：规则链按顺序执行，遇到 `should_freeze=True` 时记录后续规则不再执行（但已执行的结果仍保留）。

**原因**：冻结是最高级别动作，一旦触发无需再检查其他规则。但已执行规则的结果仍写入审计日志，保证可追溯。

### Q4：为什么懒创建 AccountRiskProfile / StrategyRiskProfile？

**决策**：首次访问时自动创建配置行，并从旧字段迁移初始值。

**原因**：
1. 避免一次性批量迁移所有账户/策略（可能有大量数据）
2. 只有实际被风控检查到的账户/策略才需要配置行
3. 迁移过程对用户透明，无需手动操作
