## 2. 各 WP 详细说明

### WP-01 CORS 收敛
- **配置**：`config.py` 新增 `APP_CORS_ORIGINS: str = ""`（逗号分隔白名单；空=通配）
- **生效**：`main.py:_parse_cors_origins()` 解析配置；通配符模式下强制 `allow_credentials=False`，杜绝 CSRF
- **启动校验**：生产 + 通配符组合 → 写 warning 日志
- **验收**：
  ```
  curl -i -X OPTIONS http://127.0.0.1:8011/api/info \
    -H "Origin: https://app.fwquant.com" \
    -H "Access-Control-Request-Method: GET"
  → HTTP 200 + Access-Control-Allow-Origin: *
  ```

### WP-02 启动密钥校验
- **函数**：`main.py:_validate_production_secret()`
- **规则**（仅生产模式生效）：
  1. 拒绝 `change-me` 默认值
  2. 拒绝长度 < 32
  3. 拒绝纯字母/纯数字
  4. 不通过则 `RuntimeError` 退出
- **生成方式**：`python -c "import secrets;print(secrets.token_urlsafe(32))"`
- **.env.example** 已更新注释

### WP-03 登录限流 + LoginAttempt 审计
- **限流实现**：`fwsort/rate_limit.py` 基于 Redis 滑动窗口（ZSet score=时间戳）
  - IP + 邮箱双维度隔离
  - 失败 5 次 → 锁 15 分钟
  - 注册：同 IP 3 次/小时
- **审计持久化**：新增 `login_attempt` 表（`fwsort/models.py`）
  - 字段：id / email / ip / success / user_agent / reason / created_at
  - 索引：email / ip / created_at
  - 迁移：`fwsort/migrations.py:_NEW_TABLES_DDL`（SQLite/PostgreSQL 双语法）
- **接入**：`router/auth_router.py` 失败/成功都写审计（不抛错兜底）

### WP-04 管理员鉴权
- **函数**：`router/admin_router.py:_bootstrap_or_admin()`
- **三种模式**：
  1. **首次启动**（无 admin 且 `APP_ALLOW_INIT=True`）→ 放行 init / seed-admin / seed-mock
  2. **已有 admin + 无 token** → 抛 `AuthError`
  3. **已有 admin + 非 admin token** → 抛 `PermissionError_`
- 手动触发任务 `require_admin` 强制 role ≥ 3

### WP-05 软删除
- **模型字段**：`ExecutionAccount.deleted_at: Mapped[datetime | None]`（indexed）
- **删除接口**：`DELETE /api/agent/accounts/{id}` 改为 `acc.deleted_at = now() + acc.status=2`
- **查询过滤**（5 处）：
  - `agent_router.list_my_accounts`
  - `agent_router.delete_account`
  - `ranking_router.global_ranking` / `list_ranking` / `ranking_change` / `my_ranking`
  - `follow_router.subscribe`（leader 校验）
- **历史保留**：`OrderExecutionLog / VoteDecision / StrategyPerformance` 的 `account_id` 仍指向原账户，审计链路不断

## 4. 风险与遗留

| 风险 | 缓解措施 |
| --- | --- |
| 限流依赖 Redis；Redis 不可用时退化为不限制 | 启动日志打印 warning；生产部署前确保 Redis 高可用 |
| LoginAttempt 表无清理策略，长期会膨胀 | 下个迭代加归档（WP-09 阶段处理） |
| 软删除后跟单/榜单仍可见 1 次 | 前端列表已过滤 deleted_at，剩余的 P99 命中数据库即可 |
| _parse_cors_origins 中星号 + credentials=False | 与 RFC 6454 一致；生产环境用白名单组合即可恢复 credentials |
