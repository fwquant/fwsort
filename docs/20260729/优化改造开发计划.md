## 阶段 D1 · 🛡️ 安全基线（必做，阻塞项）

**目标**：把"上线即裸奔"的安全漏洞一次性补齐，确保最小可上线标准。

### WP-01 ｜ CORS 收敛（修复 S-1）
- **改动点**：
  - `config.py`：新增 `APP_CORS_ORIGINS: str = "*"` 字段（按逗号分隔）。
  - `main.py`：将 `allow_origins=["*"]` 改为按配置解析列表；当 `APP_CORS_ORIGINS != "*"` 且 `allow_credentials=True` 时强制显式白名单。
- **验收**：
  - `.env` 设 `APP_CORS_ORIGINS=https://app.fwquant.com,https://admin.fwquant.com` 后，生产前端跨域访问正常；
  - 浏览器预检 `OPTIONS` 头返回 `Access-Control-Allow-Origin` 为白名单内值；
  - `*` + `credentials=true` 组合被后端拒绝并打 warning。

### WP-02 ｜ 启动密钥校验（修复 S-2）
- **改动点**：
  - `config.py`：新增 `validate_secret_key()` 方法；
  - `main.py` 的 `lifespan` 启动钩子：若 `APP_ENV=production` 且 `APP_SECRET_KEY` 等于 `change-me` / 长度 < 32，**直接抛 RuntimeError 退出**；
  - `.env.example`：注释强烈提示生成方式 `python -c "import secrets;print(secrets.token_urlsafe(32))"`。
- **验收**：
  - 生产模式 + 默认密钥 → 进程启动失败并提示；
  - 密钥 ≥ 32 位 → 正常启动；
  - 开发模式 + 默认密钥 → 仍然 warning 启动。

### WP-03 ｜ 登录/注册限流（修复 S-3）
- **改动点**：
  - 新增 `fwsort/security/rate_limit.py`：基于 Redis 的滑动窗口（IP + 邮箱双 key）；失败 5 次锁 15 分钟。
  - `auth_router.py`：在 `login / register / refresh` 入口前置依赖。
  - `models.py`：新增 `LoginAttempt` 表（持久化失败记录，支持审计）。
- **验收**：
  - 同 IP 5 分钟内 10 次登录失败 → 第 11 次返回 `429 too many attempts`；
  - 同邮箱 5 次失败 → 锁定 15 分钟，提示"邮箱已临时锁定"；
  - 正常用户登录不受影响；
  - pytest 覆盖：限流命中、过期释放、白名单内通过。

### WP-04 ｜ 管理员初始化端点鉴权（修复 S-12）
- **改动点**：
  - `admin_router.py`：`init-db / seed-admin / seed-mock / seed-rental-agents` 全部加 `Depends(require_admin)`（除 `init-db` 允许首次未授权执行，由 `settings.APP_ALLOW_INIT` 控制）。
  - 首次启动时若检测到无 admin，自动放行 `init-db`；之后任何未鉴权调用都 401/403。
- **验收**：
  - 匿名调用 `POST /api/admin/init-db`（非首次）→ 401；
  - 持有 admin token → 正常执行；
  - 文档更新：README 中"初始化"步骤拆出"首次引导"和"日常维护"。

### WP-05 ｜ 软删除 + 真正解绑 FK（修复 S-6）
- **改动点**：
  - `models.py`：`ExecutionAccount` 新增 `deleted_at: Mapped[datetime | None]`；新增 `LoginAttempt` 表。
  - `agent_router.py`：
    - `delete_account` 改为软删除（`deleted_at = now()`）；
    - 历史订单/投票 `account_id` 仍保留（审计需要）；
    - 所有查询统一加 `.where(ExecutionAccount.deleted_at.is_(None))`。
  - `ranking_router.py` / `follow_router.py` 同样过滤 `deleted_at`。
- **验收**：
  - 删除账户后，`/api/agent/accounts` 不再出现该账户，但 `execution/{uid}` 历史订单仍可查；
  - 软删除账户的投票/订单统计仍计入历史榜单。

## 阶段 D2 · 🔧 功能闭环与数据隔离

**目标**：补齐"跟单自动执行"、"演示/生产数据隔离"、"权重变更重算"三大缺口。

### WP-06 ｜ 演示 / 生产模式数据层隔离（修复 F-1）
- **改动点**：
  - `config.py`：新增 `APP_DEMO_MODE: bool = False`；新增 `APP_DEMO_SQLITE_PATH: str = "./fwsort_demo.db"`。
  - `database.py` / `redis_client.py`：根据 `APP_DEMO_MODE` 切换到独立 SQLite + 内存 Redis；演示路由的 ORM session / Redis 实例与生产完全隔离。
  - `main.py`：演示路由的 `Depends(get_async_db)` 重写为 `_get_demo_db`。
  - 演示模式启动时自动 `init_db()` + 注入 MOCK 数据，无需手动播种。
- **验收**：
  - 演示模式下增删账户/触发投票仅影响 `fwsort_demo.db`；
  - 重启演示服务自动 seed 20 个账户 + 30 笔历史；
  - 切换 `APP_DEMO_MODE=false` 后访问 `/demo/*` 路由仍可工作，但走的是生产数据 + 显式警告横幅。

### WP-07 ｜ 跟单自动执行任务（修复 F-3）
- **改动点**：
  - `scheduler.py`：新增 `follow_copy_loop(db, lookback_minutes=15)` 任务；
    - 拉取最近 N 分钟内 `status=3`（已成交）的 leader 订单；
    - 对每个有效订阅（`status=1`）调用 `execute_follow_copy`；
    - 给 follower 写 `FollowOrder` + 更新 `total_followed / total_pnl / total_share_paid`。
  - `admin_router.py`：把 `follow_copy_loop` 加进 `trigger_task` 白名单。
  - 配置项 `FOLLOW_COPY_INTERVAL_MIN` 默认 5 分钟。
- **验收**：
  - 创建订阅 → leader 下单 → 5 分钟内 fan-out 跟单成交记录；
  - 利润分成按订阅模式（1/2/3）正确计算并写入 `FollowOrder.share_paid`；
  - 手动触发 `trigger/follow_copy_loop` 立即执行。

### WP-08 ｜ 权重变更触发榜单重算（修复 F-5）
- **改动点**：
  - `config_router.py`：`update_weights` 成功后调用 `ranking_engine.refresh_redis_zset(db)`。
  - `ranking_engine.py`：新增 `refresh_redis_zset()` 工具函数（按 `period_type` 全量重算 + ZSet 写入）。
  - `scheduler.py`：现有 `refresh_realtime_rank` 复用同一函数。
- **验收**：
  - 修改权重后 1 秒内 `/api/ranking/list` 排序变化反映新权重；
  - Redis ZSet 记录数 = 当前榜单行数。

### WP-09 ｜ 下单事务一致性 + ES 异步化（修复 F-2 / P-9）
- **改动点**：
  - `agent_router.py`：把 ES 写入从 `await index_order_log(...)` 改为 `asyncio.create_task(...)` 异步消费，捕获异常只记录不抛。
  - 新增 `fwsort/execution/outbox.py`：订单日志先入 `outbox_event` 表（新增模型），后台 Celery 任务消费后写 ES，失败重试 3 次。
  - `scheduler.py`：新增 `flush_outbox` 任务，每 30s 跑一次。
- **验收**：
  - 投票→下单全链路 P99 < 600ms（ES 抖动不影响主流程）；
  - ES 不可用时订单仍正常入 DB，30s 内补齐 ES；
  - pytest：mock ES 失败 → DB 仍有数据 + outbox 队列增长。

## 阶段 D3 · ⚡ 性能与缓存

**目标**：补齐关键索引、消除 N+1、引入 Redis 缓存层。

### WP-10 ｜ 数据库索引 + bulk update（修复 P-1 / P-2）
- **改动点**：
  - 新增 `fwsort/migrations/20260729_add_indexes.sql`，包含报告附录里的所有索引。
  - `notification_router.py`：`mark_all_read` 改为 `update(Notification).where(...).values(is_read=True)` 单语句。
  - `ranking_router.py`：`global_ranking` / `list_ranking` 改为 keyset 分页（`WHERE (composite_score, id) < (?, ?)`）。
  - 文档：README 新增"生产部署前必读：手动执行索引脚本"小节。
- **验收**：
  - `EXPLAIN ANALYZE` 榜单主查询走索引扫描（rows < 100）；
  - `mark_all_read` 在 1 万条通知下 < 100ms；
  - 翻页到第 10 页时延 < 50ms。

### WP-11 ｜ 模板预读 + 榜单缓存（修复 P-4 / P-6）
- **改动点**：
  - `main.py`：启动时一次性预读 8 个 HTML 模板到 `_TEMPLATE_CACHE: dict[str, str]`；运行时只在缓存中拼接。
  - `ranking_router.py`：`/list /global /history /change` 加 `set_cached(key, json, ttl=60)`，key 含 `rank_type + page + sort_by`。
  - 缓存失效：weight 更新 / 新订单 / `seed-mock` 触发 `delete_cached(prefix="fwsort:rank:")`。
- **验收**：
  - 同一榜单请求 60s 内只走缓存；
  - 模板渲染 CPU 占比下降 > 70%。

### WP-12 ｜ 模拟器异步化（修复 P-7）
- **改动点**：
  - `simulator.py`：`time.sleep(...)` → `await asyncio.sleep(...)`；`submit` 改为 `async def`。
  - 调用方 `agent_router.py` / `rental_router.py` 全部加 `await`。
- **验收**：
  - 100 并发模拟下单，P99 < 800ms；
  - pytest：100 并发下单不阻塞 event loop。

## 通用要求

### 编码规范（沿用 README 锁定区）
- 临时文件 `*.tmp` 任务完成立即删除；
- 不使用 `replace_all`（优先 Edit/Write 工具）；
- 函数/类前一行中文注释；
- 风格保持：安全 > 稳定 > 性能 > 功能 > 界面；
- 修改后保持：暗紫/明亮双主题、PC/MOBILE 响应式、FWUI 组件风格统一。

### 验证要求（每完成 1 个 WP 必做）
1. **单元/集成测试**：`pytest -q` 全绿；
2. **后端冒烟**：`python main.py` 启动 + `curl /health` + `curl /api/info`；
3. **浏览器实测**：PC + Mobile 各 1 套截图（保留 `docs/screenshots/after/` 风格）；
4. **回归**：D1 完成后必须用 MOCK 数据完整跑一遍 V1.0 投票→下单闭环。

### 提交规范
- 每个 WP 一个 commit：`D{阶段}-WP{编号}：{标题}（修复 S-? / F-? / P-? / U-? / A-?）`；
- 重大改动（涉及数据库迁移 / 中间件 / 路由）需在 `docs/开发日志_20260729.md` 追加 1 节。

### 临时文件清理
- 截图、调试脚本、MOCK 临时 SQL 等只放在 `docs/` 或 `scripts/_dev/` 下，任务完成即删。
