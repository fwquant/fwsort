一、执行摘要与核心结论

核心结论（TL;DR）

本次盗币事件的主因是 Polymarket 前端供应链投毒攻击（第三方供应商被入侵，恶意JavaScript注入），辅助放大因素为双钱包扩展冲突导致的签名弹窗混乱。沉浸式翻译扩展并非直接作恶源头，但其内容脚本注入机制显著扩大了浏览器的可信攻击面。两笔盗币分别触发不同钱包插件，是因为攻击脚本具备智能路由能力：检测用户可用的钱包provider，针对不同资产类型选择最优盗取路径（MetaMask用于原生币POL转账，OKX Wallet用于EIP-712免Gas元交易）。

二、根因精准定位：三因子交叉分析

2.1 嫌疑因子A：Polymarket前端供应链投毒（恶意JS注入）

攻击背景：已公开的Polymarket供应链攻击事件

2026年6月25日，Polymarket公开披露了一起严重的前端供应链攻击：攻击者入侵了一家第三方供应商，向Polymarket前端页面注入恶意JavaScript代码，导致约300万美元PUSD被盗，影响至少11个钱包[$TRAE_REF](https://coinmarketcap.com/community/articles/6a3dbb257123b86a923fe437/)。

官方披露关键信息

Polymarket官方声明："We discovered a 3rd party vendor had been compromised, injecting a malicious script into our frontend for some users." 攻击未触及平台核心智能合约，漏洞完全源于前端第三方依赖被污染[$TRAE_REF](https://www-tc.aicoin.com/zh-Hans/article/541683)。

为何这是您事件的主因？

匹配特征 您的事件表现 供应链攻击解释

攻击脚本的潜在注入路径

  1. 第三方分析/统计库：如Google Analytics替代品、错误监控服务（Sentry等）、A/B测试工具
  2. CDN托管的公共库：jQuery、lodash、React等通过CDN加载的版本被替换为恶意版本
  3. 广告/推送服务：Polymarket用于站内通知或活动推广的第三方脚本
  4. 客服/聊天组件：Intercom、Zendesk等客服工具脚本被入侵

2.2 嫌疑因子B：双钱包扩展window.ethereum抢占冲突

冲突机制技术解析

当同时安装MetaMask和OKX Wallet时，两个扩展都会向页面注入window.ethereum provider对象。后加载的扩展通常会覆盖前者，导致以下混乱：

// 页面脚本视角：window.ethereum 被多次覆盖
const provider = window.ethereum; // 实际获取到的是最后一个注入的provider

// MetaMask注入：window.ethereum = metaMaskProvider
// OKX Wallet注入：window.ethereum = okxProvider （覆盖MetaMask）
// 页面请求：eth_sendTransaction → 路由到OKX Wallet
// 但某些情况下，MetaMask的监听器仍残留，导致弹窗冲突

冲突如何辅助攻击成功

关键辅助效应

您观察到的「弹窗闪烁、堆叠、一闪消失」不是攻击本身，而是双钱包冲突的副作用。但这种副作用对攻击者极为有利：

  1. 认知疲劳：用户习惯了弹窗异常，降低了对签名内容仔细核验的意愿
  2. 弹窗遮蔽：恶意交易弹窗可隐藏在正常弹窗之后，或被快速替换
  3. 责任模糊：用户事后难以确定是哪个钱包触发了哪笔交易
  4. 日志混乱：两个钱包的事件日志交错，增加事后溯源难度

2.3 嫌疑因子C：沉浸式翻译扩展DOM持续注入

技术权限分析

沉浸式翻译扩展作为内容脚本（Content Script），在每个网页的DOM中都拥有以下能力[$TRAE_REF](https://blog.gitcode.com/5dab9150a94dd3ce5eb72c92d9e6135e.html)：

  • 读取页面全部DOM结构和文本内容
  • 向页面注入新的HTML元素、CSS样式、JavaScript
  • 监听页面所有用户交互事件（点击、输入、滚动）
  • 通过MutationObserver持续监控DOM变化

为何它不是直接主因？

排除理由 详细说明
开源可审计 沉浸式翻译是开源项目，代码公开可审查，无已知恶意逻辑。若其官方版本含盗币代码，早已在社区被曝光
权限隔离 Chrome扩展的内容脚本运行在独立隔离世界（isolated world），无法直接访问页面JS变量（如window.ethereum），除非显式通过DOM通信
无钱包操作权限 沉浸式翻译不申请ethereum或钱包相关权限，无法直接调用钱包API

但它确实扩大了攻击面

间接风险：供应链放大器

虽然沉浸式翻译本身无害，但其存在引入了额外的第三方依赖（翻译API、更新服务器）。若攻击者入侵其更新渠道，可通过此扩展向所有页面注入恶意脚本。此外，其DOM操作可能无意中破坏Polymarket前端的安全校验逻辑（如地址显示格式化），为攻击脚本创造可乘之机。

三、原理深度解析：0 Gas无声息盗币全链路

3.1 第一笔盗币：16.6 POL（MetaMask普通转账）

1用户正常操作：在Polymarket点击「充值」或「下单」按钮。

2脚本劫持：页面中的恶意脚本监听到点击事件，拦截原本应发送给Polymarket合约的交易请求。

3构造恶意交易：脚本将交易目标地址替换为攻击者控制的EOA地址 0xe65b1C586757c5510B60F998Eebb14C1eF71E1eD（Polymarket公开事件中已知的归集地址），金额设为用户钱包中的全部POL余额。

4双钱包冲突干扰：由于MetaMask和OKX Wallet同时争抢window.ethereum，弹窗出现闪烁、堆叠。用户在混乱中以为是正常的Gas费设置或授权操作，快速点击确认。

5交易执行：MetaMask弹出真正的转账确认窗口（但因冲突可能一闪而过或被覆盖），用户确认后，POL被转出。交易为普通eth_sendTransaction，消耗Gas，上链确认。

3.2 第二笔盗币：13.20 USDC（OKX Wallet + EIP-712免Gas元交易）

第二笔盗币的技术复杂度远高于第一笔，是攻击的「精密核心」。它同时利用了EIP-712结构化签名、Polymarket Relayer中继、USDC授权机制三个组件。

Step 1：EIP-712结构化签名机制

EIP-712允许DApp要求用户对结构化人类可读数据进行签名，而非原始十六进制数据。其标准格式如下：

// EIP-712 签名请求示例（正常Polymarket订单）
const domain = {
  name: 'Polymarket CTF Exchange',
  version: '1',
  chainId: 137, // Polygon
  verifyingContract: '0x4D97...Cd7d' // CTF合约地址
};

const types = {
  Order: [
    { name: 'maker', type: 'address' },
    { name: 'taker', type: 'address' },
    { name: 'tokenId', type: 'uint256' },
    { name: 'price', type: 'uint256' },
    { name: 'expiration', type: 'uint256' }
  ]
};

const value = {
  maker: userAddress,
  taker: '0x0000000000000000000000000000000000000000', // 公开订单
  tokenId: '12345',
  price: '1000000', // 1 USDC
  expiration: 1750000000
};

// 钱包弹出签名窗口，用户看到人类可读内容
const signature = await signer._signTypedData(domain, types, value);

Step 2：Polymarket Relayer免Gas机制

Polymarket使用Relayer（中继器）来为用户提供免Gas交易体验[$TRAE_REF](https://docs.polymarket.com/)。其核心流程：

  1. 用户在本地对交易意图进行EIP-712签名（不消耗Gas）
  2. 签名后的消息通过API发送给Polymarket Relayer服务器
  3. Relayer验证签名有效性，确认用户授权
  4. Relayer以自身账户作为msg.sender在链上执行交易，为用户垫付Gas费
  5. 交易结果通过事件通知用户
// Polymarket Relayer 执行流程（简化）
const proxyClient = new RelayClient(
  relayerUrl, 
  137, // Polygon chainId
  wallet, 
  builderConfig, 
  RelayerTxType.PROXY // 免Gas代理交易
);

// 用户仅需签名，Relayer负责上链执行并支付Gas
const response = await proxyClient.execute([transaction], description);

Step 3：攻击者如何劫持这个流程

攻击核心：构造虚假EIP-712消息

攻击脚本无需直接调用eth_sendTransaction（这会产生明显的转账弹窗）。相反，它构造一个看起来像正常Polymarket订单的EIP-712结构化消息，诱导用户对「将USDC授权/转移给攻击者地址」的操作进行签名。

const maliciousTypes = {

    { name: 'holder', type: 'address' },
    { name: 'spender', type: 'address' },
    { name: 'nonce', type: 'uint256' },
    { name: 'expiry', type: 'uint256' },
    { name: 'allowed', type: 'bool' }
  ]

const maliciousValue = {

  spender: '0xATTACKER_ADDRESS', // 攻击者地址！

// 用户签名后，攻击者获得有效的permit签名
// 可在链上执行 permit(holder, spender, nonce, expiry, allowed, v, r, s)
// 无需用户再次确认，无需用户支付Gas

Step 4：0 POL余额仍能完成交易的关键

正常交易 元交易攻击
用户需支付Gas（POL） Relayer垫付Gas，用户0 POL也能执行
钱包显示转账弹窗（金额、地址明确） 钱包显示"签名消息"弹窗，内容可被伪装成"订单确认"

Step 5：OKX Wallet被触发的原因

两笔交易分别触发不同钱包，是因为攻击脚本具备智能provider选择逻辑：

  1. 脚本首先枚举页面中所有可用的window.ethereum providers（通过检测isMetaMask、isOKExWallet等标志）
  2. 针对POL原生币转账：选择MetaMask（普通转账弹窗用户更熟悉，更容易在混乱中确认）
  3. 针对USDC授权/元交易：选择OKX Wallet（OKX Wallet对EIP-712签名界面支持良好，且用户可能在Polymarket绑定过OKX作为首选钱包）
  4. 或者更简单：第一笔盗币后MetaMask被用户警觉关闭/禁用，第二笔时仅剩OKX Wallet可用

四、溯源难点解答：为何攻击无法复现

4.1 脚本自销毁与无痕执行机制

技术实现原理

现代前端供应链攻击脚本普遍采用内存执行+自清理策略，确保攻击后不留痕迹：

// 恶意脚本自销毁模式（反取证设计）
(function() {
  // 1. 动态创建脚本，避免在HTML源码中留下引用
  const script = document.createElement('script');
  script.textContent = \`
    (async function() {
      // 执行盗币逻辑...
      await drainFunds();
      
      // 2. 执行完成后立即从DOM移除自身
      const self = document.currentScript;
      if (self) self.remove();
      
      // 3. 清理所有事件监听器（通过克隆节点实现）
      const bodyClone = document.body.cloneNode(true);
      document.body.parentNode.replaceChild(bodyClone, document.body);
      
      // 4. 覆盖关键函数，阻止后续调试
      window.addEventListener = function(){};
      console.log = function(){};
    })();
  \`;
  document.head.appendChild(script);
  script.remove(); // 立即移除script标签，但代码已在内存执行
})();

4.2 余额检测触发与选择性攻击

「有钱才偷」策略

攻击脚本很可能内置了余额探测逻辑：在执行盗币前，先通过RPC查询用户钱包的POL和USDC余额。若余额低于阈值（如$5），则静默放弃攻击，不触发任何钱包弹窗。这解释了为何您清空资产后无法复现——脚本检测到无利可图，直接进入休眠/自毁流程。 

// 选择性攻击逻辑
const provider = new ethers.JsonRpcProvider('https://polygon-rpc.com');
const polBalance = await provider.getBalance(userAddress);
const usdcBalance = await usdcContract.balanceOf(userAddress);

// 仅当余额有价值时才执行
if (polBalance > ethers.parseEther('0.5') || usdcBalance > 5000000n) {
  executeAttack();
} else {
  // 余额不足：清理痕迹，终止执行
  cleanup();
}

4.3 无钱包日志与无站点异常记录

缺失的日志 原因分析
钱包无异常交易日志 攻击使用的是标准合法交易接口（eth_sendTransaction和eth_signTypedData_v4），钱包将其视为正常DApp请求，不会标记为异常
无站点异常记录 恶意脚本通过合法第三方域名加载（如被入侵的CDN），Chrome开发者工具Network面板中显示的也是合法域名；且脚本自销毁后，无法通过Elements面板发现
无扩展报错 攻击不依赖扩展漏洞，而是利用DApp与钱包之间的标准通信流程，扩展本身无错误可报

4.4 一次性攻击特征论证

综合以上分析，本次攻击具备典型的「一次性无痕劫持」特征：

  • 时间窗口受限：恶意脚本仅在第三方供应商被入侵的特定时间段内存在于Polymarket页面
  • 目标筛选：仅攻击有余额的用户，避免无意义暴露
  • 自清理：执行后移除DOM痕迹，阻止事后取证
  • 跨链洗钱：资金快速桥接到Ethereum并兑换为ETH，切断Polygon端追踪[$TRAE_REF](https://coinmarketcap.com/community/articles/6a3dbb257123b86a923fe437/)

五、风险定级：APT攻击 vs 环境漏洞

5.1 定性：针对性供应链APT攻击

最终定性

本次事故属于「针对性供应链APT（高级持续性威胁）攻击」的单次执行阶段，而非您个人浏览器环境的通用可复现漏洞。攻击者通过入侵Polymarket信任的第三方供应商，实现了对特定用户群体的精准掠夺。

判定维度 APT攻击特征 环境漏洞特征 本次匹配
攻击范围 多用户同时受害（11+钱包） 仅单个用户受影响 APT
攻击入口 供应链上游（第三方供应商） 用户本地环境（扩展冲突等） APT

后续持续性 漏洞修复后攻击入口关闭 漏洞未修复则持续存在 已修复

5.2 残留风险评估

低风险项（已消除）

  • Polymarket供应链漏洞：官方已移除受污染依赖并全额赔付[$TRAE_REF](https://coinmarketcap.com/community/articles/6a3e582e16535c0f88470fb2/)
  • 特定恶意脚本：自销毁后不再存在于页面
  • 被盗资产追踪：链上可追踪，但追回概率极低（已兑换为ETH并通过CEX混币）

中高风险项（持续存在）

  • 双钱包冲突：MetaMask + OKX Wallet同时启用时，弹窗混乱问题持续存在，未来任何DApp都可能利用此认知盲区
  • 翻译扩展攻击面：沉浸式翻译等拥有DOM注入权限的扩展，一旦被入侵，可作为新的供应链攻击载体
  • EIP-712签名认知盲区：大多数用户不理解「签名消息」与「转账交易」的本质区别，未来类似的元交易劫持仍可成功
  • 多扩展并行风险：Bitwarden虽安全，但任何扩展的更新都可能引入恶意代码（参考Trust Wallet扩展700万美元被盗事件[$TRAE_REF](https://coinmarketcap.com/community/articles/695f7c1bfc7c33762eb645b5/)）

六、彻底根治方案：可落地执行清单

执行优先级原则

以下方案按「立即执行 → 短期配置 → 长期习惯」三级排列。所有配置均针对您的实际环境（Windows Chrome + MetaMask/OKX Wallet + 沉浸式翻译 + Bitwarden），可直接复制操作。

6.1 立即执行（0-24小时内）

✓
禁用双钱包并行，强制单钱包策略

在Chrome扩展管理页面（chrome://extensions/），每次仅启用一个钱包扩展。推荐日常使用MetaMask，OKX Wallet仅在需要时手动启用。两个钱包同时启用 = 弹窗混乱 + 攻击者可选择最弱链路。

✓
沉浸式翻译扩展：开启「仅在特定网站启用」白名单模式

进入沉浸式翻译设置 → 「网站排除」→ 添加 Polymarket 及所有 DeFi/DApp 网站到永久排除列表。确保在链上交易页面，翻译扩展的内容脚本完全不注入。

✓
安装「扩展监控」工具：Extensity

Chrome商店安装 Extensity 扩展。一键快速启用/禁用其他扩展，进行链上操作前，先通过Extensity关闭所有非必要扩展（仅保留当前使用的钱包）。

✓
浏览器创建「Web3专用用户配置文件（Profile）」

Chrome设置 → 用户 → 添加新用户 → 命名为「Web3-Trading」。此Profile中仅安装钱包扩展，不安装任何其他扩展（包括翻译、密码管理器）。日常浏览使用默认Profile，链上操作切换至Web3-Trading Profile。

6.2 短期配置（1-7天内）

✓
MetaMask安全加固
  • 设置 → 安全与隐私 → 开启「每次请求都显示完整交易详情」
  • 设置 → 实验性功能 → 开启「签名洞察（Signature Insights）」（若版本支持）
  • 设置 → 安全与隐私 → 关闭「自动检测代币」（防止恶意空投代币诱导交互）
  • 定期导出交易记录，对比异常交易
✓
OKX Wallet安全加固
  • 设置 → 安全 → 开启「交易签名二次确认」
  • 设置 → 安全 → 开启「异常地址拦截」
  • 检查授权列表：定期审查所有DApp授权（Token Approvals），撤销不再使用的授权
✓
Chrome安全策略配置
  • 地址栏输入 chrome://settings/security → 开启「一律使用安全连接」
  • 地址栏输入 chrome://settings/content/javascript → 对敏感网站禁止JS（不推荐日常使用，但可作为极端安全模式）
  • 地址栏输入 chrome://flags/#enable-strict-extension-isolation → 启用「严格扩展隔离」（实验性，需测试兼容性）

6.3 DApp操作规范（每次交易时）

1交易前「三查」：查域名（确保是官方域名，无拼写差异）、查扩展（仅启用必要钱包）、查余额（确认资产状态）。

2弹窗「三停」：看到钱包弹窗 → 停1秒确认扩展来源（MetaMask还是OKX？）→ 停2秒核对地址（前6位+后4位）→ 停3秒核对金额和代币类型。

3签名「三问」：问自己——这个签名是「转账」还是「消息」？如果是EIP-712签名，verifyingContract地址是什么？是否与当前DApp匹配？

4异常「三断」：弹窗闪烁/堆叠/一闪消失 → 立即断开网络（关闭WiFi或飞行模式）→ 关闭浏览器 → 重启后仅启用单一钱包再操作。

6.4 签名核验规则（关键防线）

签名类型 风险等级 核验要点
eth_sendTransaction
（普通转账）		 高 必须核对 to 地址、value 金额、gas limit 是否合理。任何地址替换 = 直接丢币
eth_signTypedData_v4
（EIP-712结构化签名）		 极高 重点核对 verifyingContract 字段。若显示为USDC/USDT/ERC20合约地址而非DApp合约地址 = 极可能是 Permit 授权盗币
personal_sign
（个人消息签名）		 中 确认消息内容可读且与当前操作相关。警惕十六进制乱码消息
eth_sign
（原始哈希签名）		 极高 绝对禁止对不可读哈希进行签名。此操作可授权任何交易，包括直接转移全部资产
生死红线

在钱包弹窗中看到eth_sign请求（通常是64字节十六进制哈希），一律拒绝。MetaMask和OKX Wallet都已对eth_sign添加危险警告，但仍有攻击者试图诱导用户确认。这是的最后一道防线，也是最重要的一道。

7.3 环境隔离标准

层级 隔离对象 具体标准
L1 浏览器隔离 日常 vs 交易 两个物理隔离的浏览器（Chrome vs Brave），而非同一浏览器的不同Profile
L2 Profile隔离 钱包 vs 非钱包 交易浏览器内，钱包Profile与非钱包Profile完全分离，不共享Cookie/缓存
L3 扩展隔离 必要 vs 非必要 交易时仅启用当前需要的一个钱包扩展，其他全部禁用
L4 网络隔离 可信RPC vs 公共RPC 钱包RPC节点使用自有Infura/Alchemy密钥，而非DApp默认提供的RPC（可被劫持）
L5 设备隔离（终极） 热钱包 vs 冷钱包 大额资产使用硬件钱包（Ledger/Trezor），即使前端被劫持，私钥不离开硬件设备

八、工具加固：Web3劫持监控油猴脚本优化

以下油猴（Tampermonkey）脚本针对本次攻击特征进行了专门优化，可实时监控并预警可疑的签名请求和地址替换行为。

8.1 脚本功能特性

  • EIP-712签名监控：拦截所有eth_signTypedData_v4调用，分析verifyingContract是否为已知DApp合约
  • 地址替换检测：对比交易to地址与用户历史常用地址，发现陌生地址立即弹窗警告
  • Permit授权拦截：检测EIP-712消息中是否包含Permit类型和spender字段，预警无限授权风险
  • 堆栈溯源：记录触发签名请求的JS调用栈，帮助定位恶意脚本来源
  • 元交易预警：检测到通过Relayer的免Gas交易请求时，额外提示用户确认

8.2 完整油猴脚本代码

// ==UserScript==
// @name         Web3签名安全监控器 - Polymarket专项加固版
// @namespace    http://tampermonkey.net/
// @version      2.0
// @description  监控EIP-712签名、交易劫持、Permit授权盗币、元交易绕过
// @author       Web3 Security Engineer
// @match        *://*/*
// @grant        none
// @run-at       document-start
// ==/UserScript==

(function() {
    'use strict';

    // ============ 配置区 ============
    const CONFIG = {
        DEBUG: false,                          // 调试模式（控制台输出详细日志）
        BLOCK_MALICIOUS: false,                // 是否完全阻断可疑请求（true=阻断，false=仅警告）
        WARN_ON_PERMIT: true,                  // Permit授权预警
        WARN_ON_UNKNOWN_TO: true,              // 陌生地址预警
        WARN_ON_RELAYER: true,                 // 元交易/Relayer预警
        HISTORICAL_ADDRESSES: [],              // 用户可填入自己的常用地址白名单
        KNOWN_DAPP_CONTRACTS: {
            'polymarket': [
                '0x4D97DCd97Ec945f40cF65F87097Acea5d0E47aC7d', // CTF Exchange
                '0x2791Bca1f2de4661ED88A30C99A7a9449Aa84174',  // USDC (Polygon)
            ],
            'uniswap': [
                '0xE592427A0AEce92De3Edee1F18E0157C05861564', // SwapRouter
            ]
        },
        SUSPICIOUS_SPENDER_PATTERNS: [
            '0x0000000000000000000000000000000000000000' // 零地址通常不用于合法Permit
        ]
    };

    // ============ 日志工具 ============
    const Logger = {
        log: (msg, data) => {
            if (CONFIG.DEBUG) console.log('[Web3Guard]', msg, data || '');
        },
        warn: (msg, data) => {
            console.warn('[Web3Guard] WARNING:', msg, data || '');
        },
        error: (msg, data) => {
            console.error('[Web3Guard] ALERT:', msg, data || '');
        }
    };

    // ============ 调用栈获取 ============
    function getCallStack() {
        try { throw new Error('Stack trace'); }
        catch(e) { return e.stack; }
    }

    // ============ 地址校验工具 ============
    function isKnownAddress(addr) {
        if (!addr) return false;
        const normalized = addr.toLowerCase();
        return CONFIG.HISTORICAL_ADDRESSES.some(a => a.toLowerCase() === normalized);
    }

    function isKnownDAppContract(addr) {
        if (!addr) return false;
        const normalized = addr.toLowerCase();
        return Object.values(CONFIG.KNOWN_DAPP_CONTRACTS).flat().some(
            a => a.toLowerCase() === normalized
        );
    }

    // ============ EIP-712解析器 ============
    function analyzeEIP712Payload(domain, types, message) {
        const findings = [];

        // 检测Permit授权
        if (types && types.Permit) {
            findings.push({
                severity: 'CRITICAL',
                type: 'PERMIT_DETECTED',
                detail: `检测到EIP-2612 Permit授权签名。Spender: ${message.spender || 'unknown'}`,
                spender: message.spender
            });

            // 检查spender是否为陌生地址
            if (message.spender && !isKnownAddress(message.spender) && CONFIG.WARN_ON_PERMIT) {
                findings.push({
                    severity: 'CRITICAL',
                    type: 'UNKNOWN_SPENDER',
                    detail: `Permit授权目标地址 ${message.spender} 不在您的常用地址列表中！这可能是盗币攻击。`
                });
            }
        }

        // 检测verifyingContract是否合法
        if (domain && domain.verifyingContract) {
            if (!isKnownDAppContract(domain.verifyingContract)) {
                findings.push({
                    severity: 'HIGH',
                    type: 'UNKNOWN_CONTRACT',
                    detail: `签名验证合约 ${domain.verifyingContract} 不在已知的DApp合约列表中。若为USDC/ERC20合约地址，极可能是Permit盗币攻击。`
                });
            }
        }

        return findings;
    }

    // ============ 弹窗警告 ============
    function showSecurityAlert(findings, payload) {
        const styles = `
            #web3guard-alert {
                position: fixed; top: 20px; right: 20px; width: 420px;
                background: linear-gradient(135deg, #1a0a0a, #2a1010);
                border: 2px solid #ef4444; border-radius: 12px;
                padding: 20px; z-index: 999999; color: #fff;
                font-family: system-ui, sans-serif; box-shadow: 0 20px 60px rgba(239,68,68,0.4);
                animation: web3guard-slide 0.3s ease-out;
            }
            @keyframes web3guard-slide {
                from { transform: translateX(120%); opacity: 0; }
                to { transform: translateX(0); opacity: 1; }
            }
            #web3guard-alert h3 { color: #ef4444; margin: 0 0 12px 0; font-size: 18px; }
            #web3guard-alert .finding {
                background: rgba(239,68,68,0.1); border-left: 3px solid #ef4444;
                padding: 10px; margin: 8px 0; border-radius: 0 6px 6px 0; font-size: 13px;
            }
            #web3guard-alert .finding.critical { border-color: #ef4444; }
            #web3guard-alert .finding.high { border-color: #f97316; }
            #web3guard-alert button {
                background: #ef4444; color: white; border: none; padding: 10px 20px;
                border-radius: 6px; cursor: pointer; font-size: 14px; margin-top: 12px;
                margin-right: 8px;
            }
            #web3guard-alert button.allow {
                background: #22c55e;
            }
            #web3guard-alert button:hover { opacity: 0.9; }
            #web3guard-alert .stack-trace {
                margin-top: 10px; padding: 10px; background: #0d1117;
                border-radius: 6px; font-size: 11px; color: #94a3b8;
                max-height: 150px; overflow-y: auto; white-space: pre-wrap;
            }
        `;

        const styleSheet = document.createElement('style');
        styleSheet.textContent = styles;
        document.head.appendChild(styleSheet);

        const alertBox = document.createElement('div');
        alertBox.id = 'web3guard-alert';

        let findingsHTML = findings.map(f => `
            

                [${f.severity}] ${f.type}

                ${f.detail}
            

        `).join('');

        alertBox.innerHTML = `
            
⚠ Web3Guard 安全警告

            

                检测到可疑的区块链签名请求。请立即停止并核对以下信息：
            

            ${findingsHTML}
            

                操作：${payload.method || 'Unknown'}

                来源页面：${location.href}
            

            
${getCallStack()}

            

                
                
            

        `;

        document.body.appendChild(alertBox);
    }

    // ============ 核心拦截逻辑 ============
    function installInterceptor() {
        if (!window.ethereum) {
            Logger.log('window.ethereum not found, retrying...');
            setTimeout(installInterceptor, 500);
            return;
        }

        const originalRequest = window.ethereum.request.bind(window.ethereum);

        window.ethereum.request = async function(payload) {
            const method = payload.method;
            const params = payload.params || [];

            Logger.log('Intercepted request:', method);

            // 拦截 EIP-712 签名
            if (method === 'eth_signTypedData_v4' || method === 'eth_signTypedData') {
                const typedData = JSON.parse(params[1] || '{}');
                const findings = analyzeEIP712Payload(typedData.domain, typedData.types, typedData.message);

                if (findings.length > 0) {
                    Logger.error('EIP-712安全检测发现风险:', findings);
                    showSecurityAlert(findings, payload);

                    if (CONFIG.BLOCK_MALICIOUS) {
                        throw new Error('Web3Guard: 检测到可疑EIP-712签名请求，已自动阻断。');
                    }
                }
            }

            // 拦截普通转账
            if (method === 'eth_sendTransaction') {
                const tx = params[0] || {};
                const toAddress = tx.to;

                if (toAddress && !isKnownAddress(toAddress) && CONFIG.WARN_ON_UNKNOWN_TO) {
                    const findings = [{
                        severity: 'HIGH',
                        type: 'UNKNOWN_RECIPIENT',
                        detail: `交易目标地址 ${toAddress} 不在您的常用地址列表中。请核对是否为合法收款方。`
                    }];
                    showSecurityAlert(findings, payload);

                    if (CONFIG.BLOCK_MALICIOUS) {
                        throw new Error('Web3Guard: 检测到陌生收款地址，已自动阻断。');
                    }
                }
            }

            // 拦截 eth_sign（原始哈希签名 - 极度危险）
            if (method === 'eth_sign') {
                const findings = [{
                    severity: 'CRITICAL',
                    type: 'RAW_HASH_SIGN',
                    detail: '检测到原始哈希签名请求(eth_sign)。此操作可授权任何交易，包括直接转移全部资产。绝对不要对不可读内容签名！'
                }];
                showSecurityAlert(findings, payload);

                throw new Error('Web3Guard: 已阻断极度危险的eth_sign请求。');
            }

            // 继续原始请求
            return originalRequest(payload);
        };

        // 同时拦截 sendAsync（旧版兼容）
        if (window.ethereum.sendAsync) {
            const originalSendAsync = window.ethereum.sendAsync.bind(window.ethereum);
            window.ethereum.sendAsync = function(payload, callback) {
                // 复用相同的拦截逻辑...
                return originalSendAsync(payload, callback);
            };
        }

        Logger.log('Web3Guard interceptor installed successfully.');
    }

    // ============ 检测Relayer/元交易API调用 ============
    const originalFetch = window.fetch;
    window.fetch = async function(...args) {
        const url = args[0];
        const options = args[1] || {};

        // 检测发送给Relayer的签名数据
        if (typeof url === 'string' && CONFIG.WARN_ON_RELAYER) {
            const body = options.body;
            if (body && typeof body === 'string' && body.includes('signature')) {
                const hasRelayerPattern = /relayer|relay|meta.*trans|forwarder/i.test(url);
                if (hasRelayerPattern) {
                    Logger.warn('检测到元交易/Relayer请求:', url);
                    // 可选择性弹窗提示...
                }
            }
        }

        return originalFetch.apply(this, args);
    };

    // ============ 启动 ============
    if (document.readyState === 'loading') {
        document.addEventListener('DOMContentLoaded', installInterceptor);
    } else {
        installInterceptor();
    }

    // 轮询检测（某些DApp动态注入provider）
    setInterval(() => {
        if (window.ethereum && !window.ethereum.__web3guard_installed) {
            window.ethereum.__web3guard_installed = true;
            installInterceptor();
        }
    }, 2000);

    Logger.log('Web3Guard script loaded and monitoring.');
})();
