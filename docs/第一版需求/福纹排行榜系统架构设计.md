跟单


## 一、系统概述

### 1.1 系统定位
**福纹排行榜**（FWQuant Ranking System）是量化交易绩效排行榜系统，用于横向对比多个交易策略/交易账户的实盘表现，支持多周期榜单、风险约束排名、加权打分机制。同时兼容多智能体策略协作模式，评估策略组合执行绩效。

### 1.2 核心价值
- 为量化策略提供公平透明的绩效对比平台
- 帮助策略开发者识别优秀策略特征
- 支持投资者筛选优质交易策略
- 提供策略绩效追踪与分析能力
- **多智能体策略协作绩效评估**（新增）
- **订单执行质量综合评分**（新增）

### 1.3 设计原则
| 原则 | 说明 |
|------|------|
| **数据隔离** | 实盘与模拟盘数据严格隔离，榜单独立展示 |
| **风险优先** | 最大回撤等风险指标纳入核心评分体系 |
| **可扩展性** | 支持多交易所接入、多策略类型扩展 |
| **实时性** | 分钟级榜单刷新，支持实时监控 |
| **历史回溯** | 完整历史榜单快照，支持回溯分析 |
| **安全优先** | 安全 > 稳定 > 性能 > 功能 > 界面 |
| **协作评估** | 支持多智能体策略组合绩效评估（新增） |

### 4.1 数据源接入层

#### 4.1.1 接入对象
- **策略账户/子账户**：每个策略分配唯一 UID
- **数据源**：OKX（现货/合约）、可扩展 Binance、Coinbase 等

#### 4.1.2 数据流模式
| 类型 | 说明 | 频率 |
|------|------|------|
| 实时成交推送 | WebSocket 实时接收成交数据 | 实时 |
| 定时持仓快照 | 定时抓取账户持仓状态 | 分钟级 |
| 历史 K 线同步 | 初始化或补全历史数据 | 按需 |
| 订单执行日志 | 智能体订单执行记录 | 实时 |
| 策略协作日志 | 多智能体交互记录 | 实时 |

#### 4.1.3 数据隔离机制
- **模拟盘数据流**：独立存储，榜单标识为「模拟」

- **隔离策略**：两套独立数据库表/Redis 命名空间

### 4.3 核心业务层 (core)

#### 4.3.1 数据清洗模块

**数据校验规则**
- 成交数据完整性校验
- 持仓数据一致性校验
- 异常值检测（如收益率超过阈值）
- **订单执行数据校验**（新增）

**准入门槛过滤**
| 指标 | 阈值配置 | 说明 |
|------|----------|------|
| 最低交易笔数 | ≥ 100 笔 | 过滤样本过少策略 |
| 最低运行时长 | ≥ 30 天 | 过滤短期运气策略 |
| 最低账户权益 | 可配置 | 过滤小资金策略 |
| 最低订单执行率 | ≥ 90% | 过滤执行质量差的策略（新增） |

#### 4.3.2 指标计算模块

**收益类指标**
| 指标 | 计算公式 | 说明 |
|------|----------|------|
| 累计净收益 | 期末权益 - 期初权益 | 绝对收益 |
| 年化收益率 | (期末/期初)^(365/天数) - 1 | 复利年化 |
| 夏普比率 | 超额收益 / 收益波动率 | 风险调整收益 |
| 卡玛比率 | 年化收益 / 最大回撤 | 收益回撤比 |

**风险类指标**
| 指标 | 计算公式 | 说明 |
|------|----------|------|
| 最大回撤 | max(1 - 净值/历史最高净值) | 最大亏损幅度 |
| 回撤修复时长 | 从回撤低点恢复到前高的天数 | 恢复能力 |
| 波动率 | 日收益率标准差 × √252 | 年化波动率 |
| 连续亏损次数 | 连续亏损交易的最大次数 | 稳定性 |

**交易质量类指标**
| 指标 | 计算公式 | 说明 |
|------|----------|------|
| 胜率 | 盈利笔数 / 总交易笔数 | 获胜概率 |
| 盈亏比 | 平均盈利 / 平均亏损 | 盈亏幅度比 |
| 平均持仓时长 | 总持仓时长 / 交易笔数 | 持仓周期 |
| 收益因子 | 盈利总额 / 亏损总额 | 收益效率 |

**订单执行质量指标（新增）**
| 指标 | 计算公式 | 说明 |
|------|----------|------|
| 订单执行率 | 成交订单数 / 下单总数 | 执行成功率 |
| 平均滑点 | Σ(预期价-成交价)/预期价 / 成交笔数 | 滑点控制能力 |
| 订单延迟 | 下单到成交平均时间(ms) | 执行速度 |
| 撤单率 | 撤单数量 / 下单总数 | 订单有效性 |

**多智能体协作指标（新增）**
| 指标 | 说明 |
|------|------|
| 协同收益贡献 | 组合收益 - 各策略独立收益之和 | 协同效应 |
| 策略间相关性 | 策略收益序列相关系数 | 分散度 |
| 资源利用率 | 实际使用资源 / 可用资源 | 效率 |
| 冲突解决效率 | 冲突解决时间 / 冲突发生次数 | 协调能力 |

#### 4.3.3 榜单评分引擎

**模式一：简单排序模式**
- 单一指标直接排序（如按卡玛比率排名）
- 适用于特定维度对比分析

**模式二：加权综合得分模式（福纹综合分）**
```
综合得分 = W₁×年化收益 + W₂×(1-最大回撤) + W₃×夏普比率 + W₄×盈亏比 + W₅×执行质量分
```
- W₁, W₂, W₃, W₄, W₅ 为权重系数，后台可动态调整
- 回撤做惩罚项：回撤越大，得分扣减越多
- 支持指标极值截断，避免极端数据扭曲榜单
- **执行质量分纳入综合评分**（新增）

**模式三：多智能体组合评分（新增）**
```
组合得分 = α×平均策略得分 + β×协同收益贡献 + γ×分散度得分
```
- α, β, γ 为组合权重系数
- 评估策略组合整体绩效

**榜单周期分区**
| 周期类型 | 时间范围 | 刷新频率 | 存储策略 |
|----------|----------|----------|----------|
| 实时榜 | 滚动 24h | 分钟级 | Redis ZSet |
| 日榜 | 自然日 | 每日收盘 | Redis + 快照 |
| 周榜 | 自然周 | 每周收盘 | Redis + 快照 |
| 月榜 | 自然月 | 每月收盘 | Redis + 快照 |
| 总榜 | 策略上线至今 | 每日更新 | Redis + 快照 |
| 自定义区间 | 用户指定 | 按需计算 | 临时计算 |

#### 4.3.4 多智能体协调器（新增）

**功能职责**
- 策略组合绩效评估
- 智能体交互追踪与分析
- 协同效应量化计算
- 资源分配优化建议

**协作模式支持**
| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 并行执行 | 多策略独立执行 | 策略组合分散投资 |
| 串行接力 | 策略按顺序执行 | 策略信号传递 |
| 条件触发 | 满足条件触发特定策略 | 事件驱动策略 |
| 动态分配 | 根据市场环境动态调整策略 | 自适应策略 |

#### 4.3.5 执行质量评估（新增）

**评估维度**
- 订单执行效率
- 滑点控制能力
- 风险控制执行
- 异常处理能力

**执行评分模型**
```
执行质量分 = 0.3×执行率 + 0.3×(1-滑点率) + 0.2×(1-延迟/基准延迟) + 0.2×(1-撤单率)
```

#### 4.3.6 存储管理

**热数据（当前榜单）**
- **存储介质**：Redis 有序集合 ZSet
- **用途**：承载排行榜快速分页查询
- **结构**：ZSet(榜单类型, member=uid, score=综合得分)

**冷数据（历史榜单快照）**
- **存储介质**：PostgreSQL
- **用途**：持久化每一期榜单快照
- **能力**：回溯历史榜单，支持历史排名复盘

**订单执行日志存储（新增）**
- **存储介质**：PostgreSQL + Elasticsearch
- **用途**：订单执行明细查询、审计追踪
- **保留周期**：90天

**定时任务调度**
| 任务 | 触发时机 | 执行内容 |
|------|----------|----------|
| 实时榜刷新 | 每分钟 | 重新计算并更新 Redis ZSet |
| 日榜快照 | 每日收盘 | 固化当日榜单到数据库 |
| 周榜快照 | 每周收盘 | 固化当周榜单到数据库 |
| 月榜快照 | 每月收盘 | 固化当月榜单到数据库 |
| 数据清理 | 每日凌晨 | 清理过期临时数据 |
| 执行日志归档 | 每日凌晨 | 归档超过90天的执行日志 |

## 九、安全与性能

### 9.1 安全红线
- 密钥配置通过环境变量/配置文件读取，禁止硬编码
- 外部请求全部参数校验 + 异常捕获（FastAPI Pydantic模型校验）
- 日志强制脱敏，不记录明文敏感信息
- API 限流：单用户每分钟最多 60 次请求
- **安全优先原则**：安全 > 稳定 > 性能 > 功能 > 界面
- **订单执行数据加密存储（新增）**

### 9.2 性能优化
- 耗时计算异步化（Celery），避免阻塞主线程
- 数据库使用连接池，复用连接
- 高频数据 Redis 缓存，减少数据库查询
- 接口响应目标：≤ 200ms
- **执行日志索引优化（新增）**
- **组合计算结果缓存（新增）**
